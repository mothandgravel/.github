A RECORD WE CAN FOLLOW

The long wait
is in the source.

TNT is a published tactical-network test platform. Its authors used military VHF radios in a controlled wired bench, with changing network conditions. This view reconstructs one published round from its sender and receiver CSVs. We did not operate the original hardware.

The original files report 7.3% packet loss for this capture. Here a missing receive row is shown as “not observed” only when the full published record is in view. Before that, the record remains awaiting an observation. No arrival is interpolated.

Recorded one-way delay retains the source clocks’ relationship. The CSV timestamps carry no timezone; we have not independently verified clock calibration. Replay runs from the first send to the last recorded event. The publisher’s duration spans the first receive to the last receive; neither is an independent capture-stop timestamp. Changing display speed changes no measurement.

REPRODUCE THE ACCOUNT

Keep the source.
Keep the awkward part.

IPv4 packet IDs repeat in this run. A naive lookup that keeps the last occurrence collapses 1,000 sender rows to 994 keys and produces five negative apparent delays. Matching each flow’s chronological occurrences reproduces the publisher’s counts and recorded delay statistics. This is an assumption for these files, not a general identity guarantee.

The original CSVs, their hashes, matching method and deterministic builder travel with the study. The publisher’s repository declares GPL-3.0; the source data and this derived dataset are supplied with that licence and attribution.
